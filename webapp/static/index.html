Nested Code → JSON
Structure extraction console

What this is

A pipeline that reads one Python file and reports its structure as JSON: every scope (module, class, function, method), the control-flow blocks inside each, and the relations between them (calls, recursion, mutual recursion, inheritance).

It is the OPORD→JSON architecture pointed at code. The stages are unchanged, and so is the reason for each one.

Architecture

Download SVG

Three bands: the dataset is generated and measured, a file is extracted and scored against its own AST, and the result is stored and read. The green path is ground truth — it needs no model and no annotation, which is what makes the score on the right meaningful.

The one thing code gives you that orders did not

An OPORD needs a human to write its gold record, because only a human knows what an order means. A Python file does not have that problem — the parser already knows. So app/gold.py reads ground truth straight out of the AST, and every run is scored against truth as it happens, with no annotation step at all.

Modules

Record schema

The shape the model must answer in, and the shape gold is produced in — so they are directly comparable. Full schema at assets/schema/nested_code_schema_v1.json.

Two conventions that decide what the numbers mean

  • elif counts as a level deeper. Python represents it as a nested If, so an if/elif/elif ladder is three levels of branch nesting. The dataset manifest was measured the same way, so scope depth and manifest depth agree.
  • A call is a relation only when it resolves to a scope in the same file. len, print and imports are not structure, and recording them would bury the signal in noise.
